## 1. How to use this document

Each phase below is self-contained and has five fixed sections:

| Section | Purpose |
| --- | --- |
| **Goal** | One sentence — what must be true when the phase ends |
| **Files** | Every file to create or modify in this phase |
| **Cursor prompt** | A copy-paste block to hand to Cursor verbatim |
| **Verify** | The exact commands that prove the phase worked |
| **Exit gate** | The checklist that must be fully ticked before moving on |

**Operating rules**

1. **Paste one phase prompt at a time.** Do not paste the whole document — it will produce a shallow, sprawling implementation.
2. **Never let Cursor skip the verify step.** A phase that "looks done" but fails its gate is not done.
3. **Commit per phase** using the suggested message. This gives you a working rollback point and a clean demo history.
4. **If Cursor deviates from `architecture.md`**, stop and make it revert or explicitly update `architecture.md`. Docs and code must not drift.
5. **Guardrail code is not negotiable.** Phases 6 and 7 encode the hard compliance rules. If Cursor "simplifies" them, restore the spec.

**Reference files Cursor should read before each phase**

```
docs/PRD.md           — what must be built (FR/NFR/A IDs)
docs/architecture.md  — how it is built (components, contracts, ADRs)
docs/implementation.md— this file (what to build now, in what order)
```

## 2. Global invariants (true in every phase)

These hold from the first commit to the last. If any is broken, the milestone fails.

| # | Invariant | Enforced from |
| --- | --- | --- |
| I1 | The LLM never sees anything except retrieved chunk text on the factual path | Phase 6 |
| I2 | Citations and the `Last updated from sources:` line are generated by **Python from chunk metadata**, never by the LLM | Phase 6 |
| I3 | Every cited URL must be in the ingested source allowlist | Phase 6 |
| I4 | PII is screened by regex **before** any model call, and the input is discarded on a hit | Phase 7 |
| I5 | Raw user query text is never written to disk or logs | Phase 7 |
| I6 | Every failure path ends in a refusal, never in a fabricated answer | Phase 6 |
| I7 | Ingestion is idempotent — re-running does not duplicate chunks | Phase 4 |
| I8 | Answers are ≤ 3 sentences with exactly one source link | Phase 6 |

## Phase 2 — Loader and cleaner (Flow A, stage 1)

**Goal** — Every enabled URL is fetched, cleaned to main readable text, snapshotted raw + clean, and hashed; failures are logged rather than silently producing empty documents.

**Files**

```
ingest/load.py
ingest/run_ingest.py        (skeleton; full pipeline wiring comes in Phase 4)
data/manifest.json          (generated)
tests/test_extract.py
tests/test_loader_contract.py
```

**Cursor prompt**

```text
Read docs/architecture.md sections 5.1, 5.2 and 10 (error handling). Read the Document
dataclass in rag/schemas.py that you already wrote.

Implement ingest/load.py - Flow A, stage "Loading". Requirements from
docs/architecture.md FR-1.2 to FR-1.6.

1. fetch(rows: list[ManifestRow], *, timeout: int = 30, raw_dir: Path) -> list[Document]
   - iterate rows; for each: GET with a realistic User-Agent, a timeout, and
     session retry (max 2 attempts, exponential backoff on 429/5xx).
   - record http_status on the Document ALWAYS (including failures).
   - on non-200 or exception: log one structured line
     {"stage":"load","source_id":...,"http_status":...,"outcome":"failed"} and CONTINUE.
     Never raise out of the loop for a single bad URL.
   - on success: write the byte-faithful response to data/raw/{source_id}.html.
   - compute sha256 over the raw bytes.
   - retrieved_at = UTC ISO-8601 timestamp, assigned at fetch time (this is what feeds
     the "Last updated from sources" line later - get it right).

2. extract(doc: Document) -> tuple[str, int]
   - parse with BeautifulSoup (lxml parser).
   - remove: script, style, noscript, nav, header, footer, aside, form, iframe,
     and any element whose class or id matches /cookie|consent|ad-|advert|banner|popup/i.
   - prefer <main>, then <article>, then role="main", then <body> - first match wins.
   - collapse 3+ blank lines to 1, strip trailing whitespace per line.
   - return (clean_text, len(clean_text)).
   - MUST be pure and offline: no network. Signature takes a Document, not a URL.

3. load_all(rows, *, raw_dir, clean_dir, timeout) -> list[Document]
   - calls fetch then extract for each document
   - writes clean text to data/clean/{source_id}.txt
   - sets content_chars, clean_path, raw_path
   - FLAGS a document as thin if content_chars < 200: set a `thin: bool` field and log
     {"stage":"load","outcome":"thin_page"}. This is the mitigation for risk R2
     (JS-rendered pages yielding no text). Add `thin: bool = False` to the Document dataclass.

4. write_manifest(docs, *, path) - writes data/manifest.json containing:
   {"generated_at":..., "embedding_model":..., "dimension":384, "documents":[...]}
   with every Document field serialised. It is the single source of truth for the citation
   allowlist used later.

5. url_allowlist(manifest_path) -> set[str] - reads manifest.json and returns the set of
   source_url values. This function is the basis of validator gate G4; keep it pure.

6. ingest/run_ingest.py for now: a CLI that loads the manifest, runs load_all, writes
   data/manifest.json, and prints a summary table (source_id, http_status, chars, thin).
   It must exit non-zero ONLY if zero documents loaded successfully. Accept --timeout
   and --manifest flags. Structure it so Phases 3 and 4 can insert stages without rewrite.

Rules: requests + beautifulsoup4 + lxml only. Respect robots.txt politeness with a simple
crawl delay of 1s per request. Structured JSON logging via a helper in ingest/load.py
for now; Phase 7 moves it to rag/logging_utils.py. Never log response bodies.
Every public function gets a Google-style docstring.
```

## Phase 3 — Chunker (Flow A, stage 2)

**Goal** — Documents are profiled then split by shape so FAQ pairs and table rows stay intact, every chunk is tagged with `field_type`, and the decision is recorded.

**Files**

```
ingest/chunk.py
tests/test_chunking.py
docs/chunking_rationale.md
```

**Cursor prompt**

```text
Read docs/architecture.md sections 5.3 and 5.4 carefully. This phase implements
docs/PRD.md FR-2.1 to FR-2.5. The chunking strategy must be DECIDED FROM THE REAL DATA,
not hardcoded blindly - docs/architecture.md §5.4 lists a table keyed on detected shape.

Implement ingest/chunk.py.

1. profile(text: str) -> DocShape
   Heuristics, in priority order:
   - FAQ: 3+ occurrences of a question-like line (ends with "?" or starts with Q\d/Question)
     AND an answer follows it. Also match /(frequently asked|faq)/i in the first 500 chars.
   - TABLE: 3+ lines that look like delimited rows (2+ pipes, or 2+ runs of 2+ spaces
     used as column separators) and at least one header-looking first row.
   - NARRATIVE: fallback.
   Return the DocShape enum. MUST be pure and offline.

2. tag_field_type(text: str, section: str) -> str | None
   Deterministic RULES ONLY - no LLM, no embeddings. Search `section` first (heading is
   the strongest signal), then the chunk body. Return one of the 15 values in
   rag.schemas.FIELD_TYPES, or "other", or None if nothing matches.
   Required mappings, match case-insensitively:
   - expense_ratio      : "expense ratio", "ter", "annual recurring", "ongoing charge"
                          (guard: do NOT match "total expense ratio" differently - treat
                          "total expense ratio" as expense_ratio too)
   - exit_load          : "exit load", "exit charge", "redemption charge", "premium on exit"
   - min_sip            : "minimum sip", "min sip", "minimum monthly investment", "sip starts"
   - min_lumpsum        : "minimum lump", "min lumpsum", "minimum investment amount"
   - lock_in            : "lock-in", "lock in period", "lock-in period", "3 years"
   - tax_benefit        : "80c", "section 80c", "tax benefit", "tax saving", "eligibility"
   - riskometer         : "riskometer", "riskometer level", "risk level"
   - benchmark          : "benchmark", "benchmark index", "nifty", "bse", "trix", "sensex"
   - nav                : "nav", "net asset value", "navs"
   - fund_manager       : "fund manager", "managed by", "pm"
   - scheme_type        : "direct plan", "regular plan", "growth plan", "dividend"
   - direct_vs_regular  : "regular plan", "direct plan", "direct vs regular", "plan option"
                          (note: this is SEPARATE from scheme_type on purpose - it is the
                          defence against risk R4, MiniLM blurring direct vs regular)
   - document_download  : "download", "how to download", "e-statement", "e-statement"
   - statement_guide    : "capital gains", "tax statement", "tax report", "statement download"
   - tax_report         : "tax report", "capital gains statement", "tax proof", "26as"
   Most specific wins when several match: order of precedence is
   exit_load > direct_vs_regular > min_sip > lock_in > expense_ratio > riskometer >
   benchmark > tax_benefit > statement_guide > tax_report > document_download >
   min_lumpsum > nav > fund_manager > scheme_type > other.

3. build_chunks(docs: list[Document], *, cfg: ChunkConfig) -> list[Chunk]
   Read target_tokens, min_tokens, max_tokens, overlap_pct from config.yaml
   (600 / 200 / 800 / 12). Per document:
   - profile it
   - FAQ shape: ONE question+answer pair per chunk. NEVER split a pair across chunks.
     If a single pair exceeds max_tokens, keep it whole and allow the overflow.
   - TABLE shape: ONE row per chunk, and the header row is PREPENDED to every chunk
     text so each row is self-describing.
   - NARRATIVE shape: heading-anchored recursive split - split on markdown-style or
     plain headings first, then paragraphs, then sentences, until each piece is under
     max_tokens. Merge adjacent small pieces up to target_tokens. Apply
     overlap_pct overlap between consecutive chunks.
   - compute ordinal (0-based position within the document)
   - compute chunk_id = sha256(f"{source_id}::{ordinal}").hexdigest()[:16]
   - carry over the Document metadata onto the Chunk (source_id, scheme, and via
     store.py later also category/doc_type/source_url/publisher/retrieved_at)
   - run tag_field_type on (text, section) and store the result
   - drop chunks with 0 characters after strip
   Return the flat list across all documents.

4. write_chunks(chunks, path) - writes data/chunks/chunks.jsonl, one JSON object per line,
   so chunks are inspectable by eye for the demo.

5. tests/test_chunking.py:
   - a synthetic FAQ document produces one chunk per Q+A pair, and NO chunk contains
     half a pair (assert every chunk with a "?" also has its answer text)
   - a synthetic fee table produces one chunk per row, and every chunk contains the
     column header
   - a long narrative produces chunks within max_tokens with > 0 overlap
   - tag_field_type returns expense_ratio for "Expense ratio: 1.24%", exit_load for
     "Exit load: 1% if redeemed within 12 months", lock_in for "Lock-in period: 3 years"
   - chunk_id is deterministic: same input twice gives identical ids
   - every produced Chunk has a field_type that is in rag.schemas.FIELD_TYPES

6. docs/chunking_rationale.md: a short markdown file stating which DocShape was detected
   for each of the 5 scheme pages, the strategy chosen for each, the final parameters
   used, and WHY - citing the failure mode you avoided (fixed-size splitting destroys
   Q+A pairs and table rows). This is the FR-2.5 deliverable and goes into the README.

Rules: pure and offline - no network, no LLM, no embedding calls. Use a simple
token estimate (len(text.split()) * 1.3 rounded) and say so in a comment; do not add a
tokenizer dependency.
```

**Files**

```

Makefile                    (wire the ingest target)

```

**Cursor prompt**

```text
Read docs/architecture.md sections 5.2, 5.5 and 10. This phase implements
docs/PRD.md FR-3.1 to FR-4.3 and FR-1.4.

Implement ingest/embed.py:

1. get_model(model_name: str) -> SentenceTransformer
   Load "sentence-transformers/all-MiniLM-L6-v2" once and cache it with functools.lru_cache.
   CPU only - do not move it to GPU.

2. embed_chunks(chunks: list[Chunk], *, cfg: EmbedConfig) -> list[list[float]]
   - model.encode(texts, batch_size=32, normalize_embeddings=True,
     show_progress_bar=True, convert_to_numpy=True)
   - assert every returned vector has length cfg.dimension (384) - raise a clear error
     naming both numbers if not. This guard catches a silent model swap.
   - return a list of lists so it is JSON/log friendly

Implement ingest/store.py:

3. open_collection(*, persist_dir, collection_name, dimension, rebuild: bool = False)
   - chromadb.PersistentClient(path=str(persist_dir))
   - get_or_create_collection(name=collection_name, metadata={"hnsw:space":"cosine",
     "embedding_model": cfg.embedding.model, "dimension": cfg.embedding.dimension})
   - if rebuild: delete the collection first, then recreate
   - IMPORTANT: if an existing collection's stored "dimension" differs from cfg.dimension,
     RAISE a clear error telling the user to run with --rebuild. Do not silently write
     mismatched vectors. This is FR-4.2.

4. upsert(collection, chunks, vectors) -> int
   - collection.upsert(ids=[c.chunk_id], embeddings=vectors, documents=[c.text],
     metadatas=[...])
   - Each metadatas dict must contain EXACTLY these keys, all as str or int (Chroma does
     not accept None or nested objects):
       scheme, category, doc_type, field_type, section, source_url, publisher,
       retrieved_at, ordinal, source_id
     Convert any None to the string "none" - a None value will crash the insert.
   - return the number of chunks written

5. COUNT guard: before upserting, if the collection already holds >= len(chunks) documents
   with the same ids, skip the write and log {"stage":"store","outcome":"already_current"}.
   This is FR-4.2 idempotency.

Complete ingest/run_ingest.py so it runs the FULL Flow A pipeline:
   manifest -> load_all -> write_manifest -> build_chunks -> write_chunks
            -> embed_chunks -> open_collection -> upsert -> print summary
Print a summary: documents loaded, thin pages, chunks created, field_type histogram,
vectors written, collection count, total wall-clock seconds.
Accept flags: --manifest, --timeout, --rebuild, --limit.
Exit 0 on success; exit 1 only if zero chunks were produced.

Makefile: the `ingest` target runs `python -m ingest.run_ingest`.

tests/test_store_idempotency.py:
  - use a tmp_path persistent dir
  - upsert 5 dummy chunks, assert collection.count() == 5
  - upsert the SAME 5 chunks again, assert count is STILL 5 (not 10)
  - open with a mismatched dimension and assert it raises

Rules: chromadb and sentence-transformers only. No network calls. sentence-transformers
downloads the model weights on FIRST use only - after that it is fully offline
(architecture.md NFR-9). Do not hardcode any path; read everything from config.yaml.
```

## Appendix C — Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `thin: true` on a scheme page | JS-rendered page, no text in HTML | Enable the Phase 1 primary-source row for that scheme and fill the real URL (R2) |
| Collection empty at query time | Ingest never ran | `make ingest` |
| Dimension mismatch error | Embedding model changed | `python -m ingest.run_ingest --rebuild` |
| Every answer is "not in my sources" | Floor too high, or chunks empty | Check `top_score` in the trace; lower `similarity_floor`; confirm `data/chunks/chunks.jsonl` is non-empty |
| Wrong scheme's facts returned | `resolve_scheme` missed a variant name | Add the variant to the tolerant match table in `rag/retrieve.py`; add a case to `test_scoping.py` |
| Direct vs regular confused | `field_type` boost too low, or not tagged | Check the chunk's `field_type` in the trace; raise the boost; add the missing keyword to `rag/fieldmap.py` |
| Citation refused by G4 | Retrieved a chunk whose `source_url` is not in `manifest.json` | The manifest and the store are out of sync — re-run `make ingest` |
| Answer rejected by G6 every time | Rounding/formatting mismatch | Loosen the numeric comparison to strip `,` and `%` on both sides; do not remove the gate |
| Refusal always returned | LLM key missing or provider misconfigured | Check `.env`; confirm `LLM_PROVIDER`/`LLM_MODEL` are set |
| First `make ingest` is slow | Model download | ~90 MB once; offline thereafter (NFR-9) |
| Live NAV question returns OUT_OF_SCOPE | Working as designed | FR-7.5; the corpus is static by design (R3) |
